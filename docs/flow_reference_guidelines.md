# 通用流程参考指引

> 适用对象：任意需要在桌面/浏览器里执行“固定流程”操作的任务，不限于小红书。  
> 目标：先查文档再行动，确保有流程依据时就按文档执行，没有文档时也能给出说明并落地任务。

## 1. 开始执行前

1. 解析用户输入，提取关键要素：产品/网站、目标动作、限制条件。
2. 在 `docs/` 目录查找是否存在与关键词匹配的流程文档。优先匹配命名模式：
   - `docs/<平台>_*flow*.md`
   - `docs/<平台>_*guide*.md`
   - `docs/*workflow*.md`
3. 如果找到文档，记录文档路径与标题，在回复中说明“已按某文档执行”。
4. 如未找到文档：在回复里备注“暂无参考文档”，继续下一步但要保持保守操作。

## 2. 执行阶段

- **有文档时**：
  - 严格按文档列出的步骤、校验点、风险处理执行；
  - 不得跳过“必填检查/确认门”等安全步骤；
  - 如果实际页面与文档不符，先尝试恢复或提示用户更新文档。
- **无文档时**：
  - 使用默认策略（例如先检查标题/正文是否空、遇到导航问题走恢复流程）；
  - 每完成一大步都记录“为什么这么做”，以便后续补文档。

## 3. 结果汇报

1. 说明流程来源：
   - “参考文档：`docs/xhs_longform_flow.md`”；
   - 或 “未找到匹配文档，本次按通用策略执行”。
2. 总结关键动作（打开站点→填表→发布等），突出任何异常或恢复步骤。
3. 如果任务失败，列出卡住原因并建议用户更新/新增流程文档。

## 4. 新文档建议

- 当碰到全新平台或流程时，执行完毕后建议用户补充文档：
  1. 简述任务；
  2. 列出可观察成功条件；
  3. 罗列风险/恢复操作。
- 文档命名建议：`docs/<平台>_<动作>_flow.md`，便于自动检索。

## 5. 快速自检清单

- [ ] 是否在执行前检索过 `docs/`？
- [ ] 执行时是否引用了文档中的关键步骤？
- [ ] 是否在结果里说明了文档使用情况？
- [ ] 若文档缺失/过期，是否提示用户需要更新？

遵循以上指引，可以让“自然语言小白命令”自动映射到已有流程；一旦流程缺失，也能及时提示并沉淀资料。
